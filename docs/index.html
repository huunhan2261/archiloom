Detailing and family housekeeping, without the click marathon.

ArchiLoom is a Revit ribbon tab of small, sharp tools for the work nobody schedules time for: renaming families in bulk, syncing detail type data through Excel, laying out detail items, and reusing sheet layouts. Every dialog follows one UI standard, so you learn the pattern once.

FAQ
When something misbehaves
Most issues are a stale pyRevit cache. Reload first, then read on.
The tab doesn't appear in Revit
pyRevit → Settings → Custom Extensions Directories → add the folder that contains ArchiLoom.extension (not the extension folder itself), then Reload. If it still hides, check that pyRevit loaded at all — a failed CLR load takes every extension with it.
A dialog opens with the wrong colours
Old cached styles. Reload pyRevit; if one window is still off, its XAML predates UI Standard v2 and its header is written inline. That's cosmetic — the tool runs fine.
"Cannot find resource named ..."
apply_theme(self) must be called before forms.WPFWindow.__init__(self, xaml). LoadComponent resolves every StaticResource immediately, so a theme merged afterwards arrives too late.
Numbers show up in feet
Revit stores length in feet internally. Every ArchiLoom dialog displays and accepts mm and converts on the way in and out — if you see feet, you're reading a raw parameter, not a tool field.
Can I undo a batch run?
Yes. Every model change is wrapped in a single transaction named after the tool, so one Ctrl+Z reverts the whole run — 24 renames included.
Which Revit versions are supported?
2021 through 2026, on pyRevit's IronPython 2.7 engine. Nothing in the codebase depends on a version-specific API, but new releases are only smoke-tested on 2024 and 2026.
Contributing
Issues and pull requests are welcome. New tools copy _TEMPLATE_window.xaml and _TEMPLATE_script.py, keep code and comments in English, and follow the shared style guide in lib/GUI/Resources/UI_GUIDELINE.md — a dialog that invents its own colour won't be merged.
